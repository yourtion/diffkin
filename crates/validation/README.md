# Trusted local validation adapter

`prepare(spec, store, cancel)` resolves candidate and optional baseline refs to commits and complete Git trees. It creates a reviewable `ValidationPlan`; it never runs project commands. `run(store, plan_id, target, cancel, emit)` must only be called after the user approves that exact plan. It runs one target with the same command identity. `history`, `load_plan`, `load_result`, and startup-only `recover_interrupted` provide persisted records.

Candidate assembly reads raw Git blobs, including unchanged files. Git hooks, filters, lazy fetch, global/system configuration and remote protocols are disabled. Symlinks, gitlinks, LFS pointers, and declared checkout transformations make the plan non-executable. Worktree/index snapshots and partially assembled SDK candidates are not supported. Store paths must be outside the repository; the plans and runs directory chains cannot be symlinks. Filesystem case/Unicode aliases that merge distinct Git paths are rejected. Every execution copies the verified snapshot into `store/runs/<result-id>/source`; artifacts from previous runs cannot affect a later run. Captured source files, executable modes and program bytes are checked before/after execution. Source-manifest corruption after execution is indeterminate.

Plan integrity covers all serialized fields. Source identity covers paths, executable bits, sizes and SHA-256 bytes. Command identity covers canonical program path, executable bytes, ordered argv, relative working directory, timeout and environment policy. Lockfile identities are recorded. These local integrity checks detect accidental/stale state; they are not cryptographic attestation against a hostile host.

The environment contains only a fixed PATH, CI=1, C locale, and per-run HOME/TMPDIR. Commands requiring dependencies or toolchain configuration outside that environment can fail. Installed dependencies, dynamically loaded libraries, transitive executables and cross-repository SDK assembly remain **unconfirmed**, even when a command passes. A passed result means exit code 0 and unchanged captured files/program, not end-to-end dependency verification.

This adapter executes trusted local programs, not a security sandbox. Programs can access the host and network, deliberately detach, or transiently rewrite and restore files. Host CPU, memory, generated artifact size and network use are not sandboxed. Only captured files are checked; generated outputs are not reused. Persistent plans, full run copies and logs currently require manual retention management.

Unix commands use a separate process group with nonblocking stdout/stderr. Cancellation and timeout send TERM, then KILL after 150 ms; ordinary descendants are stopped even when the group leader exits. IO errors and unwinding also kill and reap the child. Windows execution is explicitly unsupported. OS advisory locks prevent duplicate runs and release after crashes; recovery acquires the lock before marking a persisted Running result Interrupted. Old PIDs are never killed during recovery because of PID reuse. Detached processes surviving an application crash may require manual cleanup.

Bounds: assembly 30 seconds, 10,000 files, 8 MiB per file, 64 MiB total source; argv 256 elements/64 KiB; timeout 1–3600 seconds; executable hashing 256 MiB; emitted/persisted JSONL 1 MiB and at most 4096 records; result tail 64 KiB and 256 records. History scans at most 10,000 records and returns at most 100. Log sequences begin at 1 and remain contiguous across emitted records; truncation is explicit.

The integration tests create temporary repositories and run controlled commands written by the tests. They do not execute scripts from the user's repository. Tests cover complete capture, baseline/candidate identity, unchanged user workspace/index, Unicode/CRLF/executable modes, source/program/plan modifications, unsupported candidate types, live cancellation/timeout and child liveness, log bounds, restart recovery, concurrent locking and storage symlink rejection.
