## M3 实际范围

工作区配置保存稳定的仓库 ID、显示名、路径映射和各自的比较模式/ref。一次捕获逐个固定仓库；每个仓库仍使用已有的 commits / staged / unstaged / worktree 语义。跨仓库捕获没有全局原子事务，严格同步输入应先固定提交。

| 场景                        | 当前行为                                                                                      |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| 多个仓库都有 `src/index.ts` | 仓库 ID、仓库快照 ID 和文件内容身份共同定位，不按显示路径混用                                 |
| 仓库没有改动                | 保存仓库及比较身份作为上下文；不归档全部未变化文件正文                                        |
| 某个仓库不存在或捕获失败    | 保留该仓库的局部错误，其他仓库仍可查看                                                        |
| 路径迁移                    | 修改配置中的路径后重新捕获，保留仓库 ID；历史快照继续指向原冻结证据                           |
| 重新捕获相同内容            | 创建新的工作区快照 ID；旧审查及关系不自动成为当前结论                                         |
| 恢复历史                    | 读取本机归档并持久化所选 active snapshot，不重读活动源码                                      |
| 手工关联                    | 绑定双侧仓库、快照、文件、内容摘要及 schema/rule；不推断自动跨仓契约                          |
| 默认导出                    | 仅版本身份、文件对象身份/状态、审查状态和关系端点；无源码、绝对路径、显示标签、备注和错误文本 |

`EvidenceBasis` 由后端从真实冻结文件生成。普通文本使用当前分析规则版本；元数据/不可细化内容使用 `metadata-v1`。写入审查或关联时核对完整依据及当前工作区快照；历史规则可以保留为历史记录，不能以旧规则冒充当前分析。

### 本机持久化与上限

当前实现是 **有界 JSON，不是 SQLite**。`WorkspaceStore` 位于平台应用数据目录的 `workspaces` 下，只管理指定 ID 对应的文件；没有扫描源码目录或导入任意本机文件的接口。

- 最多 16 个工作区；每个配置 1–8 个仓库。
- 每个工作区最多 8 个快照、256 条手工关系、4096 条审查记录；关联备注最多 4096 字节。
- 单个归档最多 64 MiB，全部工作区归档最多 256 MiB。固定 `.pending` 暂存文件在崩溃后最多额外占用 64 MiB，下次写入会处理该残留。
- 超限时只自动清除无审查/关系引用且非当前的旧快照；被证据引用的历史不能静默删除，空间不足则拒绝新捕获。
- OS 文件锁串行写入，临时文件落盘后原子替换。校验 JSON envelope、字段、计数、引用与完整文本对应的 Git blob 身份。Unix 归档权限为 `0600`。
- 拒绝管理根目录、锁、暂存文件及归档文件的符号链接；恢复前检查管理根未被重定向。损坏归档明确报错，不用活动源码补齐。

内存中保留最近两个工作区快照，与原有单仓比较并存；淘汰内存项不删除持久证据。更大历史索引、数据库迁移和专门的存储清理界面留待后续。

## M4 实际范围

验证由独立的 `crates/validation` 提供。准备计划只固定输入并生成可核对的计划，不运行项目命令；用户审阅该计划后，点击运行候选或基线才执行。修改表单不修改已经生成的计划。

| 项目           | 已实现与限制                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 输入           | **单仓库 commit-only**；候选和可选基线 ref 先解析成固定 commit/tree。工作区和 index 改动不进入验证         |
| 候选装配       | 从原始 Git blob 复制完整提交树，包含未变化文件；每次运行再建立新副本，不复用前次生成物                     |
| Git 行为       | 禁用 hooks、filters、lazy fetch、replacement refs、全局/系统配置与远程协议；缺对象或不完整候选不能通过     |
| 不支持输入     | symlink、gitlink、LFS 指针、声明 checkout 转换的候选，以及文件系统大小写/Unicode 别名碰撞；显示阻塞原因    |
| 计划身份       | 绑定完整序列化计划、源码路径/模式/大小/内容摘要、规范化程序路径和字节、argv 顺序、工作目录、超时、环境策略 |
| 依赖           | 记录锁文件身份；实际安装依赖、动态库、传递程序和跨仓 SDK 装配始终标为 **unconfirmed**                      |
| 运行环境       | 固定 PATH、CI、C locale，单次 HOME/TMPDIR；不继承完整用户 shell 环境，不自动安装依赖                       |
| 支持执行的平台 | Unix 可信本机 Adapter；Windows 不执行，准备阶段返回 `Unsupported`，尚无 Windows 进程树执行 Adapter         |
| 日志与取消     | stdout/stderr 有界增量记录，截断显式；Unix 进程组 TERM 后等待 150 ms 再 KILL，正常子进程纳入取消/超时处理  |
| 运行后核验     | 检查已捕获文件、可执行位与程序字节；改写源码、程序变化或身份无法核验时不能标为原版本通过                   |
| 基线对照       | 同一计划、同一命令身份分别运行基线和候选；保留各自源码身份。当前提供对照记录，不自动判断根因               |

**这是可信本机执行，不是安全沙箱。** 程序可访问主机文件与网络，也可能主动脱离进程组；没有 CPU、内存、生成物大小或网络隔离。前后摘要不能证明程序从未临时修改再恢复文件。用户应只运行已经信任并明确批准的程序与参数。

`passed` 只表示这次单仓固定版本命令退出码为 0，并且纳入核验的源码/程序未改变。它不证明完整工具链、依赖装配或多仓联合候选已经验证。调用方仍使用发布版 SDK 时，界面继续显示依赖未确认，不能把单仓通过解释为联合通过。

### 结果、恢复与资源边界

结果状态为 `running / passed / failed / not-run / indeterminate / cancelled / interrupted / env-error`。启动失败是环境错误；超时或核验不足是结果不确定；旧结果始终保留原计划、命令和源码身份。

正常退出先关闭新任务入口、取消已有任务，并等待工作线程释放资源。启动恢复取得 OS 锁后将遗留 `running` 记录改为 `interrupted`，不会自动继续命令，也**不会杀死旧 PID**，避免 PID 重用误伤。应用异常终止后仍存活的脱离进程可能需要人工处理。

装配预算为 30 秒、10,000 文件、单文件 8 MiB、总源码 64 MiB；参数最多 256 项/64 KiB；执行超时 1–3600 秒；程序哈希最多 256 MiB。单次 JSONL 日志最多 1 MiB/4096 条，结果尾部最多 64 KiB/256 条；历史最多扫描 10,000 条并返回 100 条。完整计划、运行源码副本、日志及生成物目前仍需手动管理保留空间，尚无自动总磁盘回收策略。

详见 [Adapter 说明](../../crates/validation/README.md)及[实现](../../crates/validation/src/lib.rs)。本地完整性校验不是针对恶意主机的密码学证明。

## 尚未通过的产品门槛

- 因锁屏由用户暂缓的原生窗口交互、实际 Tauri IPC、安装/升级体验验收。
- 当前版本的冷启动、全进程峰值内存与完整性能场景；已有本地包体积不替代运行性能验收。
- 真实用户反馈与跨平台真实安装验收；Windows 验证执行仍未支持。
- 可确认依赖/工具链的联合候选装配、沙箱 Adapter、自动存储回收与迁移。
- AI 风险引导、自动契约推断、自动 rebase、签名/公证和自动更新。

M3/M4 已建立可运行实现与工程回归，以上项目继续作为明确的后续验收或未实现范围，不因里程碑编号推进而自动完成。
