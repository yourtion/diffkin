## 实现后补充组合检查

`crates/analysis/tests/holdout.rs` 在首轮实现后追加 13 组组合输入，包括同函数移动+局部改名+条件编辑+排版、ASI 与移动、可选链括号、指令注释移位、TS overload、对象方法作用域、捕获、Vue 模板/slot 绑定以及混合换行。

这是同一工程代理追加的检查，不能称为独立外部盲测。首次运行暴露“未支持的嵌套绑定分析没有解释原因”；修复后明确返回局部 scope 的 fallback 文案，新增隐藏作用域拒绝规则，所有预期保持不变并通过。没有因此放宽可折叠范围。

混合函数显示 `move + rename + edit`，保留内部修改子事件和全部原始编辑。`format` 目前专指完整 CST/token 相同的格式证明；含条件/名称变化的同一函数不会额外标为可折叠 `format`。同文件其他独立纯排版区域仍可提供格式事件。这是明确的能力边界。

## 预算与取消

解析器使用进度回调。敏感节点遍历、签名、绑定、引用路径、覆盖归组均检查预算/取消；绑定路径还限制深度为 256、累计路径单元为 1,000,000。超预算、解析错误或取消不能发布部分格式证明。

格式证明保留所有 token 和字符串/正则等原始字节；注释、模板和 JSX 敏感区域不自动折叠。嵌套函数/方法、动态查找、解构、属性简写、额外类型作用域、引用增删与名称碰撞不确认局部改名，并给出解释。

## 内核实测

原始 30 次样本、环境、源码摘要见 [kernel-benchmark.json](results/kernel-benchmark.json)。命令：

```sh
cargo run -p diffkin-analysis --example benchmark --release
```

| 场景                       | p50       | p95       | 最大值    | 结果                                       |
| -------------------------- | --------- | --------- | --------- | ------------------------------------------ |
| 1,000 个函数、单处条件变更 | 15.293 ms | 21.614 ms | 37.309 ms | 结构完成，无回退                           |
| 移动 + 改名 + 条件编辑     | 0.063 ms  | 0.075 ms  | 0.146 ms  | 保留内部修改                               |
| 2 MiB 输入预算拒绝         | 0.062 ms  | 0.073 ms  | 0.236 ms  | 明确 input-too-large，由应用提供大文件呈现 |

环境为 macOS 27.2 arm64、Rust 1.97.0 release；硬件型号未能在沙箱读取。开发机有其他并发工作，因此这些值仅为工程观察。计时只含 Rust 内核暖进程，未测系统冷启动、Git 捕获、IPC、WebView 可见延迟、空闲/峰值内存或滚动帧耗时，不能代替质量计划中的完整性能门槛。
