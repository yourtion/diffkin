# 大仓库、仓库导航与本地设置验收

日期：2026-10-28。版本：0.3.0-alpha.1。核心修复、本地工程回归及 macOS ARM 打包核验已完成；远端 CI 在实际完成后补录。原生交互仍待验收。

上一版本 M3/M4 的三平台 CI、四目标产物和 SHA-256 校验见 [0.3.0-alpha.0 记录](m3-m4.md)，不代表本轮版本已通过。

## 问题复现

用户在默认“全部本地改动”模式输入仓库路径并打开时，遇到 `Git output exceeded the snapshot limit` 与 `Repository exceeds 50,000 index entries`。

已用真实 Git 合成仓库复现：50,001 条索引仅一处暂存改动触发总索引数量限制；30,000 条长路径索引仅一处改动触发 80 MiB Git 输出限制。原测试运行约 1.08 秒，失败来自真实 capture 路径。

## 捕获方式与性能范围

提交与暂存比较使用变化路径元数据，不再为少量改动保存全仓树清单。工作区流式扫描索引和文件元数据，Unix 上完整且非 racy 的 index/stat 记录可用于快速路径；候选、特殊索引标记、转换相关内容仍读取原文。索引身份也改为流式哈希。没有简单提高全仓数量或输出缓冲阈值。

默认快速模式反映 Git stat 缓存依据，不能证明所有未修改文件从未受历史转换影响。勾选“完整原文核验”或 CLI `--verify-all` 会对已跟踪工作区文件逐一读取原始字节；未知历史转换规则已移除并提交的场景也可复核。两种模式均保留实际变化最多 2,000 路径、64 MiB 冻结内容、20 秒捕获预算和取消；完整核验可能因仓库规模达到时间预算并明确停止。

macOS 上 50,001 个真实文件、1 处改动的默认捕获实测约 2.97 秒（debug，含完整元数据复核）；该测量不能推广为所有仓库或平台性能。Windows 缺少同等 stat 证明时保守读取正文；不宣称具有相同提速。

回归覆盖超 50,000 索引、旧输出超过 80 MiB 的长路径清单、巨大提交树仅一处修改、真实默认工作区，以及特殊 flags、CRLF、弱化 stat 配置、全局/缺失/修改/历史 attributes。

已对 CodeAtlas、lynx-html-renderer、vue-json-ui-editor 三个既有固定提交重新捕获：58 个文件的冻结正文、元数据及分析结果与旧捕获逐项一致，81 个源码对象哈希复核通过，三个原仓 index 均未改变。见[差分记录](results/core-real-repositories-alpha1.json)。这些是提交模式的真实语料回归，不是用户所报巨型仓的现场验证。

## 仓库导航

- 原生目录选择支持取消，主比较栏与多仓库设置均可使用；⌘/Ctrl O 打开目录选择。
- 来源/目标支持本地分支、远程跟踪分支、标签及手动输入 commit/ref。
- 引用发现最多保留 4096 个匹配项，分页上限 200，1 MiB 输出、单次 Git 调用 5 秒；超限保留提示与手输入口。搜索覆盖完整引用名与 Unicode 子串。
- 普通引用发现不获取远端对象，不修改分支或检出状态。
- 真实 Git 回归 7 项已通过；原生目录对话框的真实选择/取消仍待验收。

## 本地设置

偏好保存于应用数据目录的 settings.json，schemaVersion=1。内容为比较表单、最近 8 个仓库和视图偏好；不保存源码、验证执行授权或自动运行命令。

存储上限 64 KiB，路径最长 4096 字节，ref 最长 1024 字节；临时文件落盘后原子替换。损坏、未知版本和非法字段明确报错并保留原文件。显式保存可恢复普通损坏文件；符号链接与目录不能被当作设置文件覆盖。

未落盘设置使用有界的 pending 快照及对应成功写入确认；重启优先恢复未确认的合法偏好，原生文件损坏时仍需显式恢复。延迟返回的旧保存不会删除更新的 pending 值。

真实文件系统回归 8 项已通过。界面已验证目录选择/取消、引用分页、手输 commit、迟到引用结果隔离、原生设置恢复、旧会话迁移、损坏文件显式恢复和延迟读写；当前59项浏览器回归全部通过，包含真实内核与既有工作区/验证输出联测；真实 Tauri IPC、系统目录对话框和 WebView 仍需原生验收。

全量回归还发现并修复了验证器此前的文件锁竞态。macOS 并行 fork 可能暂时继承锁文件描述符，仅 drop 本进程的 File 不能保证立即释放共享锁。PlanLock 现在在正常返回、早退与 panic 时显式解锁。原进程清理与同计划并发互斥继续保留。

修前相同 18 线程进程测试 30 轮中 2 次精确复现 EWOULDBLOCK，隔离控制 100 次通过；修后同条件 30/30 通过，并新增正常 drop/panic 保留 dup 引用的真实 OS 回归。详见[锁竞争证据](results/validation-lock-race-alpha1.json)。
