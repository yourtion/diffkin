# Diffkin 质量与性能计划

日期：2026-10-28。本文定义实现后的验收办法；所有数字都是初始目标，当前没有性能实测或测试通过记录。

优先级：**不误隐藏需要审查的编辑 → 对应关系正确 → 审查体验顺畅 → 降噪覆盖率与速度。** 原始覆盖完整只证明没有丢失记录，不证明折叠分类正确；两者必须分别验证。

## 1 正确性不变量

1. 每个原始编辑恰有一种覆盖处置，且可回到原始内容；源码修改、路径与文件模式变化都不能静默消失。
2. 每项格式折叠都引用语言规则和证据；heuristic、未解析区域、失败任务不能产生自动折叠证明。
3. 移动和重命名不能吞掉内部编辑，也不自动等于行为不变。
4. 结构事件范围合法、子关系无环、来源内容可定位；否则拒绝该结构结果并回退。
5. 风险、审查决定与验证结果只适用于其绑定版本；不同 generation 的异步结果不能覆盖当前视图。
6. 原始源码和显示坐标可逆映射；复制、搜索、跳转与展开不改变字节事实。
7. 普通查看不写用户源码、index 或分支；整合与验证只按获授权的具体计划运行。
8. 未执行、未覆盖、环境失败、取消和通过明确区分，任何模型文本都不能生成执行成功记录。

## 2 必须覆盖的反例

| 输入                                            | 必须保留或避免的行为                     |
| ----------------------------------------------- | ---------------------------------------- |
| 全文件格式化 + `>` 改 `>=`                      | 条件修改明确可见，不能整体折叠           |
| 函数移动 + 局部改名 + 返回值修改                | 同组展示三种变化，返回值有独立子编辑     |
| 文件前新增 30 行                                | 后续未改函数不产生移动事件               |
| 重复函数与复制粘贴                              | 歧义回退；旧位置仍在时不宣称唯一移动     |
| 同名变量、遮蔽和捕获绑定变化                    | 只关联已确认声明/引用，绑定改变保持可见  |
| `{ total }` 改成 `{ amount }`                   | 对象键变化可见，不只显示局部改名         |
| 改名同时新增/删除引用                           | 归组保留对应引用，额外增删仍可见         |
| JS `return` 后换行、可选链括号边界变化          | 不套用通用空白/括号忽略规则              |
| Python 缩进改变块归属、元组逗号变化             | 作为结构编辑保留                         |
| 字符串、模板文本、指令注释、Rust 宏 token 改变  | 不当作普通格式变化                       |
| Vue 块属性、`v-for`/slot 遮蔽、未知预处理器     | 属性可见；未支持绑定/内容明确回退        |
| 语法错误、超时、预算耗尽                        | 可见的文本回退；不保留部分错误折叠       |
| CRLF/BOM、中文、emoji、组合字符、末尾换行       | 高亮和复制正确，不越界、不错位           |
| 路径含空格/换行/非 UTF-8，文件模式/符号链接变化 | 路径无损保存、显示转义，元数据变化可见   |
| Git 过滤规则、LFS 指针、子模块更新              | 标注读取语义，不隐式执行转换或下载       |
| 分析中改文件/切版本、快速切文件                 | 旧结果不覆盖新输入，冻结内容仍可追溯     |
| SDK 候选存在但使用发布版依赖                    | 不显示联合候选验证通过                   |
| 检查过程中源码被脚本修改                        | 结果不能继续归属原输入快照               |
| rebase 中取消、崩溃、目标 ref 被推进            | 原工作保留，可恢复，最终应用拒绝过期前提 |

每个 fixture 保存双侧原始内容、元数据、应保持可见的范围、允许的折叠和关系，以及不允许的结论。期望值经人工审校；不能由待测算法直接生成后自动认可。

## 3 测试分层与评测

| 层级            | 检验什么                                                | 时机                         |
| --------------- | ------------------------------------------------------- | ---------------------------- |
| 内核用例        | 原始覆盖、语言规则、匹配、绑定、位置索引                | 每次修改相关算法             |
| 性质测试与 fuzz | 范围合法、覆盖不丢失、Unicode、畸形输入、预算终止       | PR 的有界运行 + 定期扩大语料 |
| Git 集成        | 真实小仓库历史、暂存/未暂存、浅克隆、路径、并发变化     | 修改快照或 Git Adapter 时    |
| 协议与存储      | Rust/TS DTO 一致、序号/过期响应、迁移、事务、中断恢复   | 修改契约或存储时             |
| UI 组件         | 切换视图、展开、搜索、选区、键盘、连线和滚动锚点        | 修改显示交互时               |
| 原生端到端      | 打开真实仓库到审查完成，实际 IPC、文件对话框、进程取消  | 发布候选与关键流程变更       |
| 模型与执行      | 证据引用、错误 JSON、提示注入、预算；候选依赖身份与取消 | M4/M5 后，分别独立评测       |

浏览器测试适合验证展示与交互，不能代替系统 WebView 与真实 IPC 验收。原生测试优先评估 WebdriverIO 的 Tauri 服务；当前官方文档描述了嵌入式服务的跨平台支持，直接使用 tauri-driver 的支持范围不同。测试控制插件仅在测试构建启用。[Tauri WebDriver 文档](https://v2.tauri.app/develop/tests/webdriver/)

匹配评测同时报告精确率、召回率、歧义率、回退比例、耗时和内存，并按语言/能力切片。M2 对预留的受支持案例，确认型移动/改名的精确率目标至少 98%，召回率目标至少 70%；不以置信度数字代替证据。样本数和错误案例必须随报告公开，少量案例上的百分比不能泛化到任意仓库。

危险反例中误折叠数必须为零。格式折叠另计正确折叠率；模型评测另计可操作项、重复项、错误引用和人工确认的误报。性能或召回率不达标可以收缩支持范围；已知会隐藏真实修改的规则不能发布。

## 4 初始性能预算

参考环境先选一台 16 GB 内存的 Apple Silicon Mac，M0 记录具体型号、系统/WebView、屏幕设置、工具链、Git 版本、构建参数和输入摘要。按单架构 release 包测量；参考机器外的平台独立建基线，不直接套用结论。

| 指标                  | v0.1 初始目标                | 计量边界                                              |
| --------------------- | ---------------------------- | ----------------------------------------------------- |
| 应用冷启动至可操作    | p95 ≤ 1.5 s                  | 未启动辅助进程；首次安装初始化另列                    |
| 普通提交文件列表就绪  | p95 ≤ 1 s                    | 本地 10k tracked 文件、≤100 个变更，无全仓语义索引    |
| 当前文件首个文本 diff | p95 ≤ 300 ms                 | 快照就绪后、双侧各 ≤200 KiB，无结果缓存               |
| 当前文件结构增强      | p95 ≤ 1 s                    | 同上，JS/TS，非病态输入；包括 IPC 到可见结果          |
| 已缓存文件切换        | p95 ≤ 100 ms                 | 点击到可读内容，包含渲染                              |
| 取消按钮反馈          | p95 ≤ 100 ms                 | 点击到 UI 状态变化                                    |
| 分析取消并释放占用    | p95 ≤ 250 ms                 | 合作式算法；不可中断解析必须隔离后验证                |
| 滚动帧耗时            | p95 ≤ 20 ms                  | 固定 60 Hz 场景，记录超过 50 ms 的长任务              |
| 无仓库空闲内存        | 全部应用进程合计 ≤180 MiB    | 宿主 + WebView 及其子进程，统一计量口径               |
| 普通审查内存          | 稳态 ≤350 MiB，峰值 ≤600 MiB | 包含 Git/辅助进程峰值，单独标出共享内存统计限制       |
| 空闲 CPU              | 平均 <1 个逻辑核心的 1%      | 静置 60 s，无文件变化和任务                           |
| macOS 基础包          | 下载 ≤30 MiB，安装后 ≤80 MiB | 单架构，包含 JS/TS/SFC 必要资源；不含系统 Git/WebView |

这些数字是控制“小而美”的起点，M0 以数据决定是否可行。分发报告同时列出系统依赖、额外下载和可选语言/模型成本；不能把运行时或模型进程移出统计后宣称更小。

建议初值：派生内存缓存 64 MiB、派生磁盘缓存 1 GiB、每文件结构任务软预算 1 s/上限 5 s、每实体最多 32 个精算候选。超过 2 MiB 或 50k 行的任一侧默认走大文件模式：摘要、分段文本、关闭全文件语法增强；用户主动展开受预算约束的范围。已保存快照有单独的可见存储配额，不与派生缓存混用 LRU。

若预算不足以完成细粒度文本比较，整份文件以可见的回退事件呈现，并标注“尚未细化”，允许分段读取原文；不能返回空变化或声称已经完成结构审查。

预算限制必须在分配、候选扩展和迭代中生效；超时后先回退，实际任务必须终止或按明确的有界期限释放资源。不得仅隐藏进度条，把超预算任务留在后台继续占满 CPU。

## 5 测量场景与方法

| 场景         | 输入                                                   | 观察点                                         |
| ------------ | ------------------------------------------------------ | ---------------------------------------------- |
| A 日常审查   | 10k tracked 文件，20–100 个修改文件，当前文件 ≤200 KiB | 文件列表、首个 diff、缓存切换、空闲资源        |
| B 核心价值   | 格式化 + 移动 + 改名 + 一处条件编辑                    | 真实编辑可见、配对准确、结构延迟               |
| C 极端输入   | 2 MiB/50k 行以上文件、重复代码、超长行、解析错误       | 内存上限、回退、交互与取消，不要求全量结构完成 |
| D 多仓库任务 | 3 仓库候选组合及依赖错配对照                           | 优先级、版本隔离、实际依赖身份与结果失效       |

计时标记至少包括启动、捕获开始/完成、列表就绪、文本计算、IPC、首次显示、结构计算/显示、取消请求和资源释放。系统冷缓存与应用缓存未命中是不同场景，分别记录；不要把已被 OS 缓存的读取称作磁盘冷启动。

每个普通场景至少重复 30 次，报告 p50、p95、最大值和原始记录；交替运行基线/候选构建，固定输入与后台负载。性能跑分使用专用或受控机器，波动较大的共享 CI 仅做趋势观察。新的超预算回归在发布前解决或明确收缩支持范围。

## 6 发布门槛

- 当前语言能力对应的反例、原始覆盖和过期结果测试全部通过；新增误折叠阻塞发布。
- Rust 检查、前端类型检查、相关单元/集成测试、生成协议校验和发布构建通过。
- 在所声明支持的平台完成真实安装与核心审查流程，检查数据迁移、中断恢复和卸载后的数据选择。
- 发布说明列出语言等级、已知回退、性能报告和可选功能依赖；不把实验功能计入稳定承诺。
- M4 后检查进程树取消与权限；M6 后增加候选恢复、ref 竞争和最终应用测试。

每次性能与正确性报告保留输入摘要、构建标识、规则版本和测量方法。引入新的 parser、规则或显示组件时，先运行对应语料和场景，再更新公开能力矩阵。
